# MBSC Australia website

Marketing site for MBSC Australia Pty Ltd: engineering consultancy, technical training and digital solutions for oil & gas, mining and infrastructure. Bilingual (English at `/`, French at `/fr`). Live at https://www.mbscaustralia.com.au.

## Stack

- [Astro 7](https://astro.build) static site, deployed on Vercel with the `@astrojs/vercel` adapter
- Tailwind CSS 4 with design tokens in `src/styles/global.css`
- Fonts (Manrope, Inter) self-hosted through Astro's Fonts API
- No client framework. Interactive parts (mobile menu, calendar filters, contact form) are small TypeScript scripts in `src/scripts/`
- Content Security Policy generated by Astro and emitted as HTTP headers; extra security headers added by `scripts/vercel-headers.mjs`
- Contact form posts to `src/pages/api/contact.ts`, a Vercel function that sends through Zoho Mail SMTP

## Commands

```bash
npm install          # first time
npm run dev          # http://localhost:4321 (CSP disabled in dev)
npm run build        # production build + header patch + dist checks
npm run preview:vercel   # serve the production build with headers on :4400
npm run check        # type-check .astro and .ts
npm test             # unit tests (vitest)
npm run test:e2e     # Playwright + axe against the production build
npm run format       # prettier
```

## Where things live

| Task                                                               | File                                                                        |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| Company facts (phone, email, address, ABN, ISO number, stats)      | `src/data/site.ts`                                                          |
| UI text, English and French                                        | `src/i18n/en.ts`, `src/i18n/fr.ts` (French is type-checked against English) |
| Services                                                           | `src/content/services/{en,fr}/<slug>.md`                                    |
| Case studies                                                       | `src/content/projects/{en,fr}/<slug>.md`                                    |
| Training calendars (yearly checklist: `docs/TRAINING-CALENDAR.md`) | `src/content/calendars/<year>.json`                                         |
| Client logos                                                       | `src/content/clients.json` and `src/assets/logos/clients/`                  |
| Testimonials                                                       | `src/content/testimonials.json`                                             |
| Team                                                               | `src/content/team.json`                                                     |
| Photos                                                             | `src/assets/images/` with credits in `src/data/credits.json`                |
| Page layouts                                                       | `src/views/*.astro` (routes in `src/pages/` just render a view)             |

See `docs/CONTENT-GUIDE.md` for how to edit each of these safely.

## Recurring jobs

| When                                         | Job                                                                                                    | How                                                                    |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| Every year, before 1 October                 | Add next year's public holidays, create its training calendar, move holiday clashes, generate the PDFs | [`docs/TRAINING-CALENDAR.md`](docs/TRAINING-CALENDAR.md)               |
| Whenever the leading year's calendar changes | Regenerate the PDFs (`npm run calendar:pdf`); the build fails on a stale PDF                           | same                                                                   |
| Every Monday (automatic)                     | Production rebuild so the calendar moves on by itself                                                  | `.github/workflows/weekly-rebuild.yml`, needs `VERCEL_DEPLOY_HOOK_URL` |

## Environment variables

Set in Vercel > Project > Settings > Environment Variables. See `.env.example`.

| Variable                           | Purpose                                                                                   |
| ---------------------------------- | ----------------------------------------------------------------------------------------- |
| `ZOHO_SMTP_HOST`, `ZOHO_SMTP_PORT` | Zoho SMTP server (`smtppro.zoho.com`, 465)                                                |
| `ZOHO_SMTP_USER`, `ZOHO_SMTP_PASS` | Mailbox login. Use an app-specific password. The From address is always this user.        |
| `CONTACT_TO_EMAIL`                 | Where enquiries are delivered                                                             |
| `CONTACT_FROM_EMAIL`               | Sender address. Optional with Zoho Mail; required with ZeptoMail (username `emailapikey`) |
| `CONTACT_DRY_RUN`                  | `true` logs enquiries instead of sending (local dev)                                      |
| `PUBLIC_SHOW_SAMPLE_TESTIMONIALS`  | `true` shows unapproved sample quotes (never in production)                               |

## Deployment

Pushes to `main` deploy to production through Vercel's Git integration. `.github/workflows/ci.yml` runs type checks, unit tests, the build, and Playwright on every push and pull request. `.github/workflows/weekly-rebuild.yml` triggers a Vercel deploy hook every Monday so the training calendar's default year and upcoming sessions stay current; it needs the `VERCEL_DEPLOY_HOOK_URL` repository secret.
